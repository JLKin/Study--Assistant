# 开发说明

当前桌面默认流程由 `apps/desktop/main/kernel.ts` 调用 `tools/auto-study/src/`。`packages/` 和部分脚本还保留早期阶段的能力、模拟页和验收入口，其存在不代表已向使用者开放。

## 环境与命令

建议 Windows + Node.js 24，安装 Microsoft Edge。执行 `npm.cmd ci`，再执行 `npm.cmd run setup:electron`，确保 Electron 下载完整。

| 命令                       | 用途                           |
| -------------------------- | ------------------------------ |
| `npm.cmd run typecheck`    | TypeScript 静态检查            |
| `npm.cmd test`             | 默认单元与本地集成测试         |
| `npm.cmd run build`        | 生成 `dist/`                   |
| `npm.cmd start`            | 构建并启动桌面应用             |
| `npm.cmd run package:app`  | Windows x64 打包并生成 SHA-256 |
| `npm.cmd run test:desktop` | 额外桌面与浏览器生命周期检查   |
| `npm.cmd run test:package` | 额外打包验证；需先生成包       |

默认测试使用本地测试页面；Windows 浏览器集成部分需要 Edge，其他系统可能跳过相应用例。测试通过不能替代真实平台、不同系统或长期运行验收。

## OCR 与历史验收入口

`packages/ocr/`、`vitest.ocr.config.ts` 与 `test:ocr:stage3` 属于额外实验能力。相关依赖定义在 `packages/ocr/requirements.in` 与 Windows Python 3.12 锁定文件中，不是普通桌面用户的必装项。

`acceptance-*`、`review:stage3`、`prepare:stage3` 等为开发验收工具；请先阅读代码及命令帮助，明确数据目录和操作范围，再在独立环境运行。本文不把历史验收脚本作为日常使用步骤。

## 公开源码整理

### 已知目录初始化问题

`apps/desktop/main/kernel.ts` 在 `modules()` 首次导入浏览器模块后，才在 `ensureConfig()` 设置 `ZHS_DATA_DIR`。而 `tools/auto-study/src/browser.mjs` 在模块初始化时就固定了 `DATA_DIR`、`LOG_DIR` 和 `SHOT_DIR`；打包后的 `import.meta.url` 回退还与启动目录有关。因此桌面主进程数据目录与内核实际使用的目录可能不同，不能仅按 `%APPDATA%` 判断全部登录数据的位置。

本次仅整理公开资料，未修改这段应用逻辑，也未运行真实课程。源码重建后需要独立验证目录初始化；再次分发运行过的软件目录时，还应检查启动目录及其上一级的 `data/`、`logs/`、`shots/`。本次原始发布包的静态检查未发现这些个人运行文件。

### 本次整理范围

保留应用、内核、模块、构建脚本和测试；未收录原工程中的个人运行数据、内部阶段报告与历史交付档案。`package-lock.json` 的根名称和根版本已与 `package.json` 的 `zhihuishu-study-assistant` / `0.1.0` 对齐，依赖版本未改变。

请勿提交 `data/`、浏览器配置、会话文件、日志、截图、密钥、`node_modules/`、`dist/` 或发布压缩包。软件包应作为 Releases 附件上传。
